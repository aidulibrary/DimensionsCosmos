# 校勘任务中心 v3 · 纯功能态最佳方案

> 2026-10-31 · DimensionsCosmos（维点图书馆）
> 定位：本文件只讨论"没有商业化"的任务中心应该长什么样。价格、积分、套餐、资产账面值一律不进入设计。

---

## 一、先把定性说清楚

任务中心不是收入中心，也不是流量入口。它只有一件事要做：

> **让每一处存疑文本，从「□」推进到一条可被引用的定论，并且全过程可回放。**

由此推出唯一的成功判据：**单位时间内，"有判据支撑并被复核采纳"的字位数**。
所有界面元素都必须服务于这条判据，服务不了的就不放。

---

## 二、五条设计原则

| # | 原则 | 含义 | 反面（已删除） |
|---|---|---|---|
| 1 | 任务 = 证据包 | 卡片上写的是取证路径、候选来源、验收条件，不是价格 | 「¥6.8 万 / 年」三档卡、`在库待转化资产 ¥2,244` |
| 2 | 提交与复核强制分离 | 自己不能复核自己；双盲、异人、互不可见 | 「提交即完成」的伪闭环 |
| 3 | 状态唯一且可审计 | 每条任务在任一时刻只处于一个状态，状态迁移留痕 | 多套口径并存（积分 / 悬赏 / 上架） |
| 4 | 度量只看质量与流速 | 一致率、回炉率、采纳率、卷次密度 | 积分总额、资产估值、GMV |
| 5 | 贡献以署名结算 | 采纳后校勘记署「某某校」，进致谢名单 | 悬赏、排行榜、抽佣 |

第 5 条是这套东西能长期跑下去的关键：**学术劳动的回报是署名与可引用性，不是计价**。一旦引入价格，判据就会被议价污染，双盲也会失效。

## 三、信息架构：三视图 + 一条数据链

```
        ┌──────────── 任务池（做什么） ────────────┐
        │ 按等级 / 状态 / 卷次筛选，卡片直达原文字位 │
        └───────────────┬──────────────────────────┘
                        │ 认领 → 提交
        ┌───────────────▼──────────────────────────┐
        │ 复核台（我不看自己）                       │
        │ 双盲两人 → 一致则结案 / 分歧则仲裁          │
        └───────────────┬──────────────────────────┘
                        │ 采纳 / 驳回
        ┌───────────────▼──────────────────────────┐
        │ 校勘记（已定案，可引用）                    │
        │ TEI <app> 片段 → 回填正文 → 阅读页可见      │
        └──────────────────────────────────────────┘
```

三个视图共用同一份 `data.json` 与同一套字位锚（`#ch-{chId}:b{blk}:k{kth}`），**不允许出现第二套编号**。

### 3.1 任务池
- 筛选项只保留三个维度：等级（A/B/C）、状态（可认领 / 我的 / 待复核）、卷次。
- 卡片信息按"决定是否开工"排序：等级 → 难度 → 估时 → 上下文 → 证据摘要。
- 卡片上不出现任何金额与积分；出现的是"约 N 分钟"这类**工作量估计**，用于排期，不用于计价。

### 3.2 卷次分布（本轮新增）
49 处待考散在 37 卷，如果只给一张平铺列表，人看不到"哪里吃紧"。
用 37 个色块按卷序铺开，颜色深浅 = 该卷待考密度，点击即筛出该卷任务、再点取消。
这是纯功能设计：它回答"我这一小时该去攻哪一卷"。

### 3.3 复核台（下一阶段）
- 待复核队列按"提交时间 + 等级"排序，A 级优先。
- 复核者看不到提交者身份，也看不到另一名复核者的结论。
- 一致 → 自动结案；分歧 → 进仲裁池，由第三人带证据裁决。
- 这是当前页面唯一的真实缺口：现在提交后只落到 `localStorage`，没有第二个人。

### 3.4 校勘记（下一阶段）
结案后自动生成 TEI：

```xml
<app loc="ch12:b3:k7">
  <lem>龻</lem>
  <rdg source="#hanshu">𪚥</rdg>
  <note>据《后汉书·光武帝纪上》中华书局点校本第 42 页；底本不改，异文出校记。</note>
</app>
```

校勘记列表页按"卷 → 字位"排序，供外部引用；每条带稳定锚点与署名，这是学术产品的真正资产。

## 四、状态机（唯一口径）

| 状态 | 进入条件 | 可执行动作 | 出口 |
|---|---|---|---|
| `open` 待认领 | 任务生成 | 认领、查看证据 | → `claimed` |
| `claimed` 进行中 | 有人认领 | 提交判定 / 放弃 | → `review` / 回落 `open` |
| `review` 待复核 | 提交通过机器预检 | 双盲复核 | → `agreed` / `disputed` |
| `disputed` 分歧待仲裁 | 两份结论不一致或 α < 0.80 | 第三人裁决 | → `agreed` / 回 `open`（附驳回理由） |
| `agreed` 已定案 | 一致或仲裁通过 | 生成校勘记、回填正文 | → `published` |
| `published` 已入正文 | 校勘记合入 | 只读、可回溯 | — |

规则：
- 一次只能前进一格，禁止跳态；
- 驳回必须写理由，理由进任务历史，不隐藏；
- 任何状态都可回放到"谁在何时改了什么"。

## 五、指标口径（替代原来的"资产"KPI）

| 指标 | 定义 | 用途 | 健康阈值 |
|---|---|---|---|
| 待认领数 | `open` 状态条数 | 供给是否充足 | — |
| 有取证路径率 | 存在可解析来源的条数 / 总数 | 判断任务是否"可开工" | ≥ 70% |
| 平均估时 | Σ 难度×25min / 条数 | 排期、评估批次规模 | — |
| 卷次覆盖 | 有任务的卷数 / 总卷数 | 是否只堆在少数卷 | 尽量铺开 |
| 复核一致率 | 双盲一致的条数 / 已复核条数 | 判据是否清晰 | α ≥ 0.80 |
| 回炉率 | 驳回后重开的条数 / 提交条数 | 培训与验收闸是否有效 | ≤ 15% |
| 采纳率 | `published` / 累计提交 | 真实产能 | 观察趋势 |
| 字位密度 | 每卷待考处数 | 决定下一批攻坚顺序 | — |

## 七、明确不做的事

1. 不出现任何价格、套餐、授权版本、机构方案入口；
2. 不引入积分、悬赏、排行榜、抽佣；
3. 不用"资产""变现""转化""上架"这类商业语汇描述任务；
4. 不把"提交"当"完成"——没有第二个人复核，就不算结案；
5. 不为拉新做任何入口干扰，任务中心只对"愿意读原文的人"有意义。

---

## 八、下一步建议顺序

1. **P1 复核台**：先把"异人复核"做出来，否则所有提交都停在半空（这是最大缺口）。
2. **P2 校勘记**：结案即出 TEI，让成果可被引用，署名才成立。
3. **P3 状态上云**：localStorage → 服务端，多人才可能协作。
4. **P4 批次扩容**：后汉书 40 处按同一方法论拆解，验证流程可复制。

一句话收口：**任务中心的价值不在它卖什么，而在它能不能让一处「□」变成一句有出处的话。**
