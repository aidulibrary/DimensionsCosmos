# 「解锁全部」顶栏 CTA 与任务中心导航不一致：论证与待拍板方案

日期：2026-11-03　范围：`src/layouts/BaseLayout.astro`、`src/pages/tasks/index.astro`、`src/styles/global.css`
状态：**仅论证，未改代码**，等负责人拍板。

---

## 1. 现象（实测数据）

Edge 148 + puppeteer-core，构建产物直测：

| 视口 | 页面 | 导航链接 | 「解锁全部」CTA | 工具区宽度 | 顶栏高度 |
|---|---|---|---|---|---|
| 1280 | 首页 | 首页·书库·任务中心·方法·**定价**（5） | 可见 | 236px | 82px |
| 1280 | 任务中心 | 首页·书库·任务中心·方法（4） | 无 | 132px | 82px |
| 375 | 首页 | 5 | **不可见**（`display:none`） | 120px | 109px |
| 375 | 任务中心 | 4 | 无 | 120px | 109px |

结论三条：

1. 桌面端 5 项 vs 4 项，工具区宽度差 **104px**，跨页切换时顶栏右侧视觉重心横移。
2. 移动端 CTA 根本不存在——`global.css:1036` 已用 `display:none` 隐藏，注释写明「**定价入口仍在导航链接里**」。
3. 因此「解锁全部」只在**桌面 + 非任务中心**这一种组合下出现：它既不是全站元素，也不是页面级元素，是一个**例外产物**。

## 2. 根因

不是「任务中心漏配了导航」，而是**把商业转化 CTA 放进了导航骨架**。一旦 CTA 在骨架里，每个页面就必须回答一次「要不要显示商业内容」，于是出现三套互相矛盾的机制：

| 机制 | 位置 | 隐含判断 |
|---|---|---|
| 小屏隐藏 CTA | `global.css:1036` | CTA 冗余，定价入口够了 |
| 任务中心隐藏 CTA + 定价 | `tasks/index.astro` `hideCommercial` | 该页不宜出现商业化 |
| 桌面其他页常驻 CTA | `BaseLayout.astro:304` | CTA 是全局曝光位 |

三套机制说的是同一件事的三个半答案。**任何一致性修复，本质都是把这三条收敛成一条规则。**

## 3. 两个加重问题的既有事实

1. **同目标双入口**：`nav-primary` 的「定价」与 `nav-tools` 的「解锁全部」都指向 `/pricing`（`t.nav.pricing` / `t.nav.cta`）。顶栏对同一落地页给了两个链接，语义差别（分类页 vs「全部解锁」这个 SKU）在顶栏里无法表达。
2. **文案与落地页不符**：`src/config/commerce.ts:8` `PAY_ENABLED = false`。此时 pricing / methods / guide 的价格与按钮全部降级为「限时免费 / 免费可读」。顶栏写「解锁全部」，点进去看到的是 ¥0 和限时免费——**CTA 在支付开启前是空承诺**。

## 4. 真实的商业上下文入口（已存在，不需要顶栏补位）

| 位置 | 形态 | 说明 |
|---|---|---|
| 作品页 `MethodSelector` | `🔐 付费解锁（¥a–b / 篇）` + 锁定遮罩 + `?unlock=` | 用户「想读某方法」的决策点，转化位置最准 |
| 方法页 `MethodsView` | 每张方法卡 `去解锁 →`（带 `?method=`） | 按方法聚合的转化 |
| 定价页 `PricingView` | 全部解锁包（全部 N 种方法 / 新方法自动解锁 / 投票 / B 端折扣） | 唯一能讲清 SKU 的地方 |
| 首页 hero / 页脚 | 现有 CTA 与关于·条款·退款·隐私链接 | 品牌与合规底盘 |

即：**顶栏 CTA 在商业链路上不承担任何独有职责**，它唯一作用是「桌面端恒定曝光」，代价是导航一致性 + 支付未开启时的空承诺。

## 5. 方案对比

| 方案 | 做法 | 一致性 | 改动量 | 风险 | 转化影响 |
|---|---|---|---|---|---|
| A 维持现状 | 桌面显示、任务中心隐藏 | ✗ 永久割裂 | 0 | 低 | 基线 |
| B 全站统一显示 | 删 `hideCommercial`，任务中心也显示 | ✓ | 2 行 | 低 | 略升 |
| C 顶栏撤 CTA，定价为唯一商业项 | 删 CTA，删 `hideCommercial`，`定价` 全站一致；CTA 下沉到 hero/定价页/作品页 | ✓ 结构最简 | 3 处 | 低 | 桌面恒定曝光↓，上下文曝光↑ |
| D 门控式 | 保留 CTA，但渲染条件改为 `PAY_ENABLED`；删 `hideCommercial` | ✓ 且自动随支付开关 | 3 行 | 低 | 支付开通当天自动回归 |

## 6. 推荐：C + D 合并（先 D 的结构，留 C 的终态）

立即执行（3 处、约 6 行）：

1. `BaseLayout.astro:304`：`{!hideCommercial && ...}` → `{!hideCommercial && PAY_ENABLED && ...}`，即 **CTA 由支付开关统一门控**，不再由页面类型各自决定。
2. `BaseLayout.astro:294`：`nav-primary` 里的「定价」保持**全站显示**（它是导航项，不是转化按钮）。
3. `tasks/index.astro:62`：删除 `hideCommercial={true}` → 四个页面顶栏结构完全一致，5 项对齐。

理由：

- **一致性由结构保证，不靠逐页配置**。删掉唯一一处 `hideCommercial`，`hideCommercial` 这个 prop 也就自然可以退役（或保留给未来「无导航」的独立窗口页）。
- **两套矛盾机制收敛为一条**：小屏隐藏 CTA 与支付未开启隐藏 CTA 在语义上同源——「非必要时不占导航位」。合并后规则是：*导航只放导航项；转化按钮仅在支付可用时出现*。
- **支付开通即自动恢复**，不需要第二次改代码、也不会出现「昨天上线支付、今天没人记得打开 CTA」。
- 空承诺消失：顶栏不再承诺一个落地页给不出的东西。

若进一步采纳 C 的终态（推荐作为 UX-4 之后的一步）：把「解锁全部」从顶栏永久撤下，改在 ① 定价页顶部醒目 SKU 卡、② 作品页锁定提示条、③ 页脚新增一行「全部解锁」链接 三处承载。顶栏从此只有功能项，商业表达交给上下文——这与项目在小屏上已经做过的判断一致。
