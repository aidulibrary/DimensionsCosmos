# 古籍任务中心 · 设计框架与商业化模型

**项目**：DimensionsCosmos（维点图书馆）
**版本**：v1.0 设计稿
**日期**：2026-10-31
**定位**：把「待考清单」升级为可计量、可验收、可结算的古籍整理生产系统，并以此为基础建立 B 端与数据端的商业闭环。

---

## 0. 一页结论

| 维度 | 结论 |
|---|---|
| 产品本质 | 不是"又一个古籍数据库"，而是**古籍校勘任务的分发与验收网络**：任务单元（Task Unit）= 一处存疑文本 + 证据包 + 验收标准 + 结算价 |
| 学术底座 | 国家/行业标准（GB/T 31076.1、WH/T 20、GB/T 3792.7、WH/T 66、国图 2024 数字化与知识标引规范）+ 国际数字人文标准（TEI P5 ch.12、IIIF、W3C Web Annotation、FAIR、RIDE/CSE 评审）+ 陈垣校勘四法 |
| 质量模型 | 机器预检 → 双盲复核 → 争议仲裁 → 一致性指标（Krippendorff's α≥0.80）→ 抽样审计，全程留痕可复算 |
| 现有资产 | 17 部书；资治通鉴原 590 处缺字已回填 541 处，剩 49 处（A25/B23/C1，37 卷）；存量 后汉书 40 处 + 其他书 382 处；17 部版本待升 verified |
| 任务供给 | 首批可直接上架 49 条（真实、带证据包）；第二批 422 条存量；第三批由版本核定与全书对校自动生成 |
| 商业化主轴 | **B 端机构订阅（现金牛）→ 数据/API 授权（高毛利）→ 定制整理与出版分成（项目制）→ C 端会员（流量与口碑）** |
| 三年目标（设计值） | 机构 120 家、ARR ≈ 3,300 万、数据授权占比 14%、毛利率 62% |
| 关键风险 | 内容版权与版本授权、专家供给、众包质量方差、"权威性"叙事被头部平台压制 |

## 1. 资产盘点：任务中心从哪里长出来

### 1.1 已有数据资产

| 资产 | 现状 | 对任务中心的意义 |
|---|---|---|
| 书目与正文 | 17 部，含资治通鉴 294 卷 | 任务挂载的物理对象 |
| 待考清单 | `public/collation/tj-review/data.json`，49 条 | **首批真实任务单元**，字段已接近工业级 |
| 清单字段 | no/vol/anchor/ctx/src/srcCand/vote/voteCand/wiki/grade/gradeTxt/suggest/pos/chap/chId/blk/kth/href/mark/cxk | 已构成"证据包"雏形：原文上下文、来源、候选、投票、等级、建议字、深链定位 |
| 阅读页深链 | `#ch-{chId}:b{blk}:k{kth}` | 任务 ↔ 原文双向直达，验收时可对照 |
| 存量缺口 | 后汉书 40 处、其他 15 部 382 处 | 第二批任务池 |
| 版本档案 | 17 部 reference 待升 verified | 版本核定任务线（EGV 模型） |
| 商业化雏形 | 定价页：单篇 ¥3.9–12.9、方法包 ¥49/年 | C 端价格锚点，任务中心可复用账号与支付 |

### 1.2 当前缺什么（也就是任务中心要补的）

1. **无任务对象**：清单是"问题列表"，不是"可认领的工作单元"，没有状态、责任人、截止时间、结算价。
2. **无验收协议**：grade 是静态分级，没有"谁按什么标准判定通过"。
3. **无生产角色**：没有校对者/复核者/仲裁者/机构客户四类身份。
4. **无结算与激励**：贡献不可计量、不可兑换、不可对外报价。
5. **无对外交付物**：B 端买不到"可审计的校勘成果"，只能买阅读权限。

## 2. 标准底座：三层合规矩阵

任务中心的每一处判定，都必须能指向一条可引用的标准，否则无法向机构客户交付，也无法在学术共同体中立足。

### 2.1 第一层：国家与行业标准（合法性、可交付性）

| 标准 | 用途 | 在系统中的落点 |
|---|---|---|
| 《关于推进新时代古籍工作的意见》（中办、国办，2022） | 政策依据：推进古籍数字化、建设古籍版本目录知识系统、构建古籍知识服务体系 | 对外叙事与政府/基金项目申报口径 |
| 《2021—2035 年国家古籍工作规划》 | 重点任务与工程方向 | 选题与共建书系优先级 |
| GB/T 31076.1-2014《汉文古籍特藏藏品定级 第1部分：古籍》 | 版本价值定级 | `work_profiles.grade`，决定任务优先级与定价系数 |
| WH/T 20-2006《古籍定级标准》 | 一/二/三级古籍判定 | 同上，兼容旧档 |
| GB/T 3792.7《古籍著录规则》 | 著录字段规范 | 书目元数据、版本项、藏地项 |
| WH/T 66《古籍元数据规范》 | 元数据元素集 | `work_profiles` / `instance` 字段映射 |
| 国图《古籍数字化和知识标引规范手册（暂行）》（2024） | 图像采集指标、元数据著录、结构数据、卷目篇名、**外字信息处理**、全文转换质量、命名与存储结构 | 扫描件命名、结构切分、缺字外字编码（本项目的□即外字问题）、质检抽样比例 |
| 《中华人民共和国公共图书馆法》 | 公共机构采购与开放服务 | 机构合同条款、开放共享义务 |

> 说明：国图 2024 手册中"外字信息处理"与"全文转换质量要求"两节，直接对应本项目"缺字□待考"的业务。任务中心的验收标准必须引用这两节，而不是自创口径。

### 2.2 第二层：国际数字人文标准（互操作性、学术可信度）

| 标准 | 用途 | 落点 |
|---|---|---|
| **TEI P5, ch.12 Critical Apparatus**（`app`/`lem`/`rdg`/`witness`/`listWit`） | 异文与校勘记的标准编码 | 每条任务结案后生成 TEI 片段，可直接并入数字校勘版 |
| **TEI P5, ch.11 Primary Sources** | 底本、叶面、行款描述 | 版本档案与图像对应 |
| **IIIF Image API 3.0 / Presentation API 3.0** | 书影互操作、区域级引用 | 任务详情展示底本原叶，支持 `#xywh` 区域定位 |
| **W3C Web Annotation Data Model** | 标注即资源（目标+主体+动机） | 众包标注的统一交换格式，便于导出到机构平台 |
| **FAIR 原则** | 可发现、可访问、可互操作、可复用 | 成果数据集对外授权的基本承诺 |
| **RIDE / CSE 评审标准** | 数字校勘版的学术评审清单 | 对外发布"校勘版"时的自评表 |
| Unicode CJK Ext.B–H + **UAX #59 IDS** | 缺字/外字描述（如 ⿰亻龻） | 无字可打时的标准表达，禁止私有区 PUA 造字 |
| METS/MODS、Dublin Core | 机构系统对接 | 机构版交付包 |

### 2.3 第三层：校勘学方法论（判定逻辑）

陈垣《校勘学释例》四法，直接映射为四类任务与四套验收规则：

| 校法 | 定义 | 任务类型 | 验收要点 |
|---|---|---|---|
| **对校** | 以同书祖本/别本对读，异同注旁 | T2 版本对校 | 必须指明校本（含藏地、索书号、叶次），异文逐条出校 |
| **本校** | 以本书前后互证 | T3 内部互证 | 需给出至少 2 处书内平行文例 |
| **他校** | 以他书（前引、后引、同时代文献）校本书 | T4 他源比勘 | 需给出可核查的引文出处（书名+卷次+原文） |
| **理校** | 无古本可依或诸本互异时，以专门知识考订 | T5 理校定夺 | **门槛最高**：需两名以上相应断代专家附议，且必须"存疑不改、出校记" |

配套规则（写入系统硬约束）：

1. **底本优先**：不改底本正文，异文一律入校勘记；确需改字，标注"据 X 本改"。
2. **孤证不立**：单一来源（尤其现代网络文本）不得直接定案，最高 B 级。
3. **多源独立**：A 级要求 ≥2 个相互独立信源，且至少 1 个为 A1 锚（国家出版发行信息平台 CIP / 国图 / 权威整理本）。
4. **可复算**：任何定级都能由证据向量重算，不依赖个人声望。
5. **宁缺勿滥**：证据不足保留□，进入下一轮，不做"合理猜测"式填空。

## 3. 任务中心产品架构

### 3.1 核心对象模型

```
Work（书）
 └ Instance（版本：底本/校本/参校本，含藏地、索书号、IIIF manifest）
    └ Witness（叶/行/字位）
Task（任务单元）
 ├─ target：work_id + anchor + chId/blk/kth（深链）
 ├─ type：T1 录入 | T2 对校 | T3 本校 | T4 他校 | T5 理校 | T6 仲裁 | T7 版本核定
 ├─ evidence_pack：证据向量（来源、级别、引文、链接、书影区域）
 ├─ grade：A/B/C（继承项目既有定级）
 ├─ difficulty：D1–D5（由证据缺口、字数、版本复杂度计算）
 ├─ bounty：积分 + 现金（按难度×等级系数）
 ├─ state：draft → open → claimed → submitted → reviewed → arbitrating → accepted / rejected / deferred
 ├─ assignee / reviewers[] / arbiter
 └─ audit_log[]：每次状态变更的哈希链
Submission（提交）
 ├─ proposed_text / IDS 描述
 ├─ sources[]（结构化引文）
 ├─ rationale（判据说明，必填 ≥50 字）
 └─ machine_precheck（格式、字数、来源可解析性、重复提交检测）
Review（复核）
 ├─ blind：双盲，互不可见
 ├─ verdict：accept / revise / reject
 └─ consistency：与另一复核者的 α 贡献
Settlement（结算）
 ├─ 积分、现金、署名权重
 └─ 成果版权归属与授权范围
```

### 3.2 任务七型（对应标准动作）

| 类型 | 名称 | 输入 | 输出 | 典型耗时 | 谁能做 |
|---|---|---|---|---|---|
| T1 | 文本录入/OCR 校字 | 书影 | 逐字文本 | 5–15 分钟/叶 | 大众（培训后） |
| T2 | 版本对校 | 底本+校本 | 异文表 | 30–90 分钟/卷 | 受训校对者 |
| T3 | 内部互证 | 本书多卷 | 平行文例 | 20–60 分钟/处 | 受训校对者 |
| T4 | 他源比勘 | 引文候选 | 出处核验 | 30–120 分钟/处 | 研究生成硕士以上 |
| T5 | 理校定夺 | 全部证据 | 判定+校记 | 2–8 小时/处 | 断代专家（邀约制） |
| T6 | 争议仲裁 | 冲突提交 | 终裁+理由 | 1–3 小时/件 | 学术委员会 |
| T7 | 版本核定 | CIP/国图/出版社 | verified/reference/conflict | 自动化+抽检 | 系统（EGV 模型） |

### 3.3 难度与悬赏计算（可复算公式）

```
difficulty = clamp(1, 5, 1
  + 1.2 × 证据缺口系数      # 无 A 级源=1，有 A 级源=0
  + 0.8 × 版本复杂度        # 单一底本=0，多版本互异=1
  + 0.6 × 语义歧义度        # 候选唯一=0，多候选互斥=1
  + 0.4 × 上下文缺失度 )    # 上下文完整=0，仅存单字=1

bounty_points = round( base[type] × grade_coef × (0.6 + 0.4 × difficulty) )
base: T1=10, T2=60, T3=40, T4=80, T5=240, T6=120, T7=5
grade_coef: A=1.5, B=1.0, C=0.7
```

以首批 49 条为例（A25/B23/C1），估算总悬赏约 3,900–5,200 积分，折合现金（1 积分 ≈ ¥1 结算池）约 4,000–5,000 元即可完成一轮全量攻坚——**单位成本极低，这是商业模型的起点**。

### 3.4 状态机（硬约束）

```
draft ──publish──> open ──claim──> claimed ──submit──> submitted
  ↑                                                     │
  │                                          ┌──────────┴──────────┐
  │                                    预检通过              预检失败
  │                                          ↓                      ↓
  │                                      reviewed ←── 分配双盲 ── 退回(revise)
  │                                     ┌────┴────┐
  │                                 一致通过    不一致
  │                                     ↓            ↓
  │                                 accepted    arbitrating ──> accepted / deferred
  │                                     ↓
  └──────────── deferred（证据不足，进入下一轮）<── 复核驳回(reject×2)
```

规则：
- 认领后 72 小时未提交自动释放（可续期一次）。
- 同一任务同一人不得既提交又复核（强制分离）。
- `deferred` 任务每 90 天重新进入 open，并升级悬赏 20%。
- 所有变更写入 append-only 审计日志，哈希前链。

### 3.5 质量体系（四道闸）

| 闸口 | 机制 | 阈值 | 失败处理 |
|---|---|---|---|
| ① 机器预检 | 格式、来源可解析、字符合法性（含 IDS）、与既有正文冲突检测、重复提交指纹 | 全通过 | 退回，不计次 |
| ② 双盲复核 | 两名独立复核者，互不可见 | 双方 accept | 进入仲裁 |
| ③ 一致性度量 | 任务级 + 人员级 Krippendorff's α | α≥0.80 采信；<0.60 回炉培训 | 触发复训/降权 |
| ④ 抽样审计 | 结案任务 10% 随机回抽（A 级 30%） | 错误率 ≤2% | 批量返工 + 复核者降级 |

**信誉分**：`trust = 0.5×历史通过率 + 0.3×一致性α + 0.2×时效达标率`，决定可认领的最高难度与现金单比例。

### 3.6 角色与权限

| 角色 | 权限 | 准入 |
|---|---|---|
| 访客 | 浏览任务池、查看证据包（脱敏） | 无需登录 |
| 贡献者 C1 | 认领 T1/T2，积分结算 | 通过 30 分钟培训 + 10 题测试 |
| 校对者 C2 | 认领 T3/T4，现金+积分 | 测试 85 分或 50 个 T1 通过 |
| 专家 E | 认领 T5，进入仲裁池 | 学术委员会邀约（断代/文献学背景） |
| 机构客户 B | 私有任务池、指定书系、成果导出、审计报告 | 订阅合同 |
| 学术委员会 | 终裁、标准修订、争议复核 | 内部治理 |

### 3.7 机构私有任务池（B 端关键差异化）

机构可上传自有书影与底本，形成**隔离任务池**：数据不出机构域（私有部署/专有命名空间），仅输出结构化成果与审计报告；平台按席位与任务量收费。这是把"众包平台"卖给图书馆与出版社的核心形态。

## 4. 生产工作流（从问题到资产）

```
① 任务生成（自动）
   EGV 版本核定 + 缺字扫描 + 对校差异检测
        ↓
② 证据包装配（自动）
   三源取证：CIP/国图 / 权威整理本 / 开放文本（维基文库等）
   生成证据向量 + 定级 + 难度 + 悬赏
        ↓
③ 上架（自动，人工只审例外）
   进入任务池，按书/卷/等级/难度分片
        ↓
④ 认领与提交（人）
   阅读页深链定位 → 填写判定 → 附引文 → 提交
        ↓
⑤ 预检 → 双盲复核 → 仲裁（机器+人）
        ↓
⑥ 合并入库（自动）
   写回正文/校勘记 → 生成 TEI `<app>` 片段 → 版本号+1
        ↓
⑦ 发布与结算（自动）
   站点更新 + 贡献者署名 + 积分/现金结算 + 机构报告
```

关键指标（每个环节都可埋点）：
- 任务吞吐（件/周）、平均在途时长、一次通过率、α 值、单件综合成本、机构交付准时率。

## 5. 商业化设计框架

### 5.1 价值主张（对谁说什么）

| 客户 | 痛点 | 我们给什么 | 一句话 |
|---|---|---|---|
| 高校/研究机构 | 整理成本高、成果难发表、版本不可信 | 可引用的校勘版 + TEI 数据 + 审计报告 | "把 3 年的整理工期压到 3 个月" |
| 公共图书馆 | 藏而不能用、数字化成果无法验收 | 按标准的数字化质检 + 知识标引 + 任务协作台 | "让你的馆藏变成可检索的知识系统" |
| 出版社 | 古籍选题周期长、编校人力不足 | 初校/对校产能 + 校勘记底稿 | "把编辑从对校里解放出来" |
| 中学/国际中文教育 | 读不懂、缺注解 | 导读 + 精校文本 + 教学包 | "让经典进课堂" |
| 个人研究者/爱好者 | 买不起 75 万的库、缺少参与感 | 免费阅读 + 贡献积分 + ¥199 学者版 | "你也能校一部书" |

### 5.5 收入结构判断

```
Y1：机构 62% | 项目 26% | C 端 12%
Y3：机构 51% | C 端 23% | 数据 14% | 项目 9% | 出版 3%
```

结论：**先用机构订阅养活团队，再用数据授权抬毛利，C 端只做口碑与任务供给**。不要一开始做 C 端订阅大战——古籍 C 端付费天花板极低（对比：头部平台免费开放 5.7 万部，付费空间被压缩）。

### 5.6 竞争位与护城河

| 玩家 | 形态 | 我方差异 |
|---|---|---|
| 中华经典古籍库 / 籍合网 | 整理本数据库，75 万/全套，机构授权 | 他们是"成品库"，我们是"生产线 + 可审计数据" |
| 识典古籍（字节 + 北大） | 免费阅读 + AI 整理工具 + 3.7 万志愿者 | 他们做规模与公益，我们做**质量协议与 B 端交付**；可与其工具链互补而非正面竞争 |
| 中国基本古籍库（爱如生） | 影像 + 全文，年费 12.6 万 | 我方提供版本谱系与校勘记，而非仅全文检索 |
| Transkribus | 手写识别 + 机构平台，合作社制 | 我方聚焦汉文校勘语义层（异文、理校、仲裁），不做通用 HTR |

护城河三层：
1. **数据护城河**：每条异文都有证据向量与审计链，越用越厚，无法一次性爬取复制。
2. **协议护城河**：验收标准写入合同与学术评审，机构替换成本高。
3. **网络护城河**：专家池 + 机构共建书系形成双边锁定。

### 5.7 合规与版权红线

1. 底本使用**公版**（作者逝世逾 50 年）或已获授权版本；现代整理本仅作参校并注明，不复制其校记。
2. 扫描件版权与藏地许可逐馆签约；IIIF 引用遵循机构声明。
3. 众包贡献者签署贡献者协议（CLA），明确成果著作权归平台/机构，贡献者获署名权与积分。
4. 训练数据授权必须排除"以生成内容替代原典阅读"的场景，避免与机构客户利益冲突。
5. 遵循《数据安全法》《个人信息保护法》；机构私有池物理隔离。
