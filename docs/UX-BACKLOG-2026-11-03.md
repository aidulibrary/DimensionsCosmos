# 体验优化：多维身份走查、刚性需求与任务规划（2026-11-03）

> 对象：维点图书馆 / DimensionsCosmos 站点（静态 1360 页，112 部可读，四语言）
> 方法：按八类身份各走一遍主路径（进入 → 找书 → 读 → 引用/分享），记录"第一次卡住的地方"，再把卡点聚类为刚性需求；能当场改的当场改并实测，改不动的落任务卡。
> 结论口径：**刚性 = 不做就有用户直接流失**，不是"想做得好一点"。

---

## 0. 结论摘要

**本次已落地并实测通过（7 项）**：检索从整页刷新改为即时过滤且可分享、导航补"首页"与当前页高亮、四语言合并为单一下拉、语言回落修复、移动端导航不再被隐藏、skip-link 与 `main` 地标、搜不到时的空态与本地留痕。

**新增刚性需求 5 条**：R1 检索必须真的能用、R2 任何页面必须知道自己在哪并能一键回首页、R3 语言必须是单一入口、R4 移动端必须能走完全流程、R5 找不到必须给下一步。其中 R1、R2、R3 已达成；R4 已达成骨架，触控尺寸待补；R5 达成基础版，聚合待补。

**工程量项 8 张任务卡**：UX-1 至 UX-8，本机承接 6 张，marvis 承接 2 张（详见 §5 与 `docs/WORKSPLIT-2026-11-03.md`）。

## 1. 八类身份走查

| # | 身份 | 进入方式 | 首屏第一需求 | 走查中真实卡点 | 判定 |
|---|---|---|---|---|---|
| I1 | 初步用户（朋友圈点开） | 手机、陌生链接 | 3 秒内知道"这是什么、我能干什么" | 首页气势足但缺"先读哪本"的引导；点进书库后 112 张卡片平铺，不知道从哪下手 | 高流失，需新手路径 |
| I2 | 深度用户（每日通读） | 桌面，书签直达某书 | 续读、翻章、记住位置 | 无阅读进度保存，每次回来要重新找章；章节阅读页无字号/行距调节 | 留存断点，必须补 |
| I3 | 青少年学生（12–17） | 手机，搜"论语 原文" | 快速定位到某一篇，释义能看懂 | 移动到分类与卡片时点击区偏小；检索输入全角/简繁混输易漏（现已归一化） | 中，触控待补 |
| I4 | 中老年读者（55+） | Windows 桌面 / 平板，字体放大 | 字够大、界面不晃 | 无字号切换；夜间模式已有但纸色单一；导航字距偏小 | 高，需适老 |
| I5 | 同行（其他古籍项目 / 图书馆） | 桌面，横向比较 | 有多少书、底本是什么、怎么做的 | 首页与书库未展示"底本 / 章数 / 字数"可比指标；无"关于数据"入口直达 | 中，影响合作信任 |
| I6 | 专家（版本目录学） | 桌面，核某一版本 | 底本、校记、来源可追溯 | 版本信息藏在书籍详情；详情页 `version_text` 存在但未结构化呈现（底本/校本/阙卷） | 高，专家据此判断可用性 |
| I7 | 学者（研究者） | 桌面，检索式查询 | 按作者/朝代/关键词精确定位，能导出引用 | 检索只能全文模糊匹配，无作者/朝代域限定，无排序（字数/章数），无引用导出 | 高，直接决定能否用于研究 |
| I8 | 学术（教学备课） | 桌面投屏 + 学生手机 | 一条课程化阅读路径，学生跟得上 | 无"导读 → 章节 → 讨论点"的教学路径聚合；任务中心偏商业化，教学场景无入口 | 中，属增长点 |

**跨身份观察**：八类身份的路径几乎都收敛到同一个动作——**"我要找到某一部/某一章"**。这意味着检索与定位不是功能点，而是产品的地基。I1/I3/I4 的差异主要在**呈现密度与触控/字号**，I5/I6/I7 的差异主要在**元数据显性度与可导出性**。

## 2. 刚性需求（R1–R5）

### R1 检索必须真的能用（已达成）

- 不做会怎样：用户输入"庄子"页面刷新却没反应，直接判定"这站是坏的"。
- 已做：`src/pages/books.astro` 改为构建期全量渲染 112 张卡 + 客户端即时过滤；关键词与部类可叠加；条件写入 URL（`?q=&bu=`）便于分享与前进后退；全角转半角、去空白、小写归一化；中文输入法拼写期间不打断。
- 实测：初始 112 部可见 → 输入"庄"→ 1 部（庄子）；"论"+子部 → 3 部且全部为子部；`/books/?q=庄子` 直达 1 部且输入框回填"庄子"。

### R2 任何页面必须知道自己在哪、并能一键回首页（已达成）

- 不做会怎样：从搜索引擎落到书籍详情页的用户，导航里找不到"首页"，只能后退。
- 已做：导航新增"首页"（四语言：首页 / 首頁 / Home / Inicio）；`aria-current="page"` 标记当前区（详情页仍高亮"书库"）；首个 Tab 聚焦"跳到主内容"（skip-link，实测 top=12px）。
- 实测：`/` 高亮首页、`/books` 与 `/books/13-史记/` 均高亮书库。

### R3 语言必须是单一入口，且切换后语言真的变（已达成）

- 不做会怎样：四个语言标签挤占导航，PC 端把"书库/任务/方法"挤到折行；且切到英文仍停在中文页，用户以为坏了。
- 已做：4 个胶囊合并为一个 `<details>` 下拉，摘要显示当前语言，选中项带 `aria-current`；Esc、点外部自动收起；目标语言无本页译文时改为跳该语言首页。
- 实测：`/books` 下拉列出 简体中文:`/books`、繁體中文:`/zh-TW/`、English:`/en/`、Español:`/es/`；点 English → `/en/`，`html lang=en` 且导航变 Home/Library/Tasks/Methods/Pricing。

### R4 移动端必须能走完全流程（骨架达成，触控待补）

- 不做会怎样：移动端导航把"书库/任务/方法"全部 `display:none`，手机用户只能看到品牌和 CTA，等于没有导航。
- 已做：`@media (max-width:900px)` 改为两行结构——品牌行 + 可横滚链接行，隐藏的是 CTA 而非导航本体。
- 实测（375×780）：导航可见"首页/书库/任务中心/方法"，两行共 109px，横向溢出 0，搜索框宽 330px。
- 待补（UX-4）：分类 chip 触控高度 < 44px，命中率偏低。

### R5 找不到时必须给下一步（基础版达成，聚合待补）

- 不做会怎样：搜不到就是一片空白，用户不知道是"没这本书"还是"我输错了"。
- 已做：空态分三行——标题带关键词（"没有找到匹配「xxx」的书。"）、建议（只输书名一个字 / 换分类）、告知（搜不到的词会记在本地，用来决定补哪些书）；同时写 `localStorage.dc_search_miss`（去重、留 50 条）。
- 实测：输入 `zzzznotexist` → 空态显示，`dc_search_miss` 记录该词。
- 待补（UX-5，marvis）：埋点聚合为"高频搜不到书名"周报，直接喂养补书优先级。

## 4. 共性问题聚类

1. **定位类**（I1/I2/I3/I7）：找书、找章、回到上次位置 —— 检索已修，**阅读进度与章节导航未做**（UX-2）。
2. **阅读类**（I2/I3/I4）：字号、行距、纸色、夜间 —— 仅有夜间模式，**适老与舒适度未做**（UX-3）。
3. **信任类**（I5/I6/I7）：底本、来源、阙卷、校记 —— 数据已在库（`version.text/structure/readingTip/grade/score`）但**未在界面结构化呈现**（UX-6）。
4. **学术类**（I7/I8）：域限定检索、排序、引用导出、教学路径 —— **全缺**（UX-7）。
5. **引导类**（I1/I8）：第一本书读什么、怎么读 —— **全缺**（UX-8）。

## 5. 工程量项任务卡

> 工作量按"单机、单人、含自测"估算；本机 8GB 内存，构建约 30s/次。

### UX-1 书库筛选维度扩展（P0，0.5 人日，本机）

- 现状：仅 4 个部类 chip，112 部一屏平铺，无朝代 / 可读状态 / 排序。
- 方案：`books.astro` 增加第二排筛选（朝代来自 `works[].dynasty`，状态来自 `ok/readable`）与排序（章数、字数、拼音序）；筛选状态统一进 URL（`?bu=&dyn=&sort=`）；卡片增加 `data-dyn`、`data-chars`。
- 验收：任一筛选组合的结果数 = 数据侧独立统计数；URL 可分享还原；无结果时空态正确。
- 依赖：无（`index.json` 字段已具备）。

### UX-2 阅读页体验（P0，1.5 人日，本机）—— 原文阅读页已交付（2026-11-04，c14f9f28）

- 现状：`/read/[slug]/[method]` 有正文与大师视角，但无目录侧栏、无进度、无快捷键。
- 方案：章节侧栏（服务端渲染章节列表，当前章高亮）；`localStorage` 记 `dc:progress:<slug>` = 最后章号 + 篇内比例；`[` `]` 或 `←/→` 翻章；回到书籍详情显示"继续读第 N 章"。
- 验收：刷新后回到上次章与位置；连续翻 10 章无整页闪烁；移动端侧栏可抽屉化。
- **交付结果（`/books/[slug]/read` 原文线）**：目录侧栏与章内高亮此前已具备；本轮补齐
  ① 篇内比例记忆（键 `dc:progress:<slug>`，值 `{id,title,ratio,at}`，兼容旧 `dc:last`）；
  ② 刷新/回访自动复位 + 顶部提示条「第 N 篇 · 篇内 X%」（3.2s 收起，尊重 reduced-motion）；
  ③ 详情页按钮变「继续阅读 · 第 N 篇 →」并给出上次篇名与百分比，附「从头开始读」次要出口；
  ④ 快捷键补 `[` `]`（与 `←/→` 等价，排除输入框与修饰键）。
  关键判定：翻篇会写 hash，若「有 hash 就不续读」，按 F5 时续读将永远失效——故改为「hash 指向进度那一篇且无块级锚点 → 恢复比例；指向别的篇 → 深链优先」。
  验收：Edge headless 9/9 全通过；`astro build` 1372 页 EXIT=0。

### UX-2b 大师视角页接入续读（P0，0.5 人日，本机）· 已交付

- 现状（交付前）：`/read/[slug]/[method].astro` 全文无 `localStorage`，读完即丢位置；原文线与该线进度互不相通。
- 方案：复用 `dc:progress:<slug>` 同一键，键内分区——`id/title/ratio/at` 归原文线，新增 `guides[method] = {r,at}` 归导读线；读页与原文页双向继承；读页底部「对照原文全文」入口升格为跨线出口。
- **交付结果**：
  ① 导读线进度读写（篇内比例，各视角独立一份，切换视角互不干扰）；
  ② 回访自动复位 + 顶部提示条「已回到上次读到的地方：本文 X%」（3.2s 收起，尊重 reduced-motion）；
  ③ 出口升级：「接着读原文 · 第 N 篇 →」并带出「上次原文读到《篇名》· 篇内 X%」（第 1 篇且 <3% 视为未读，不冒充续读）；
  ④ 带 hash 进入（引证深链）时深链优先，不抢滚动位置；
  ⑤ 原文页 `saveProgress` 改为「先取原对象再覆盖本线四字段」，否则整对象重建会把 `guides` 一并抹掉——两条线会互相重置，这是本轮最隐蔽的坑。
- 验收：Edge headless（CDP）15/15 全通过——含原文→导读→原文的完整往返、多视角隔离、深链优先、未上架视角页无 UI 泄漏、详情页按钮不受影响；`astro build` 1372 页 EXIT=0。

### UX-3 排版与适老（P0，1 人日，本机）· 已交付

- 方案：正文区字号档位（16/18/20/22px）、行距档（1.8/2.0/2.2）、纸色（宣纸 / 纯白 / 米黄 / 夜间），全部走 CSS 变量并记忆到 `localStorage`；触控目标 ≥44px。
- 验收：四档字号 × 三种纸色不变形；夜间模式对比度 ≥ 4.5:1（正文）。
- **交付结果（原文线 `/books/[slug]/read`，`35714cce`）**：五档字号 16/18/20/22/26px（较方案增 26px 大字号档，为老花眼兜底）、三档行距 1.8/2.0/2.2、四纸色；全部经 CSS 变量 `--reader-font` / `--reader-lh` / `data-reader-paper` 下发，设置键 `dc:reader:v1`。
- **交付结果（大师视角线 `/read/[slug]/[method]`，`2e4222e0`）**：导读页此前硬编码 16px / 1.95、无面板，本轮补齐——
  - 新增 `src/components/ReaderPrefs.astro`（floating / inline 双形态），原文线与导读线共用同一组件、同一变量、同一内存键，两线互相同步；
  - `GuideView.astro` 精读正文、`Field.astro` 各字段块改跟 `--reader-font` / `--reader-lh`（保留原字号作 fallback，未开面板时不回归版式）；
  - 纸色只换 `--paper` 等主题变量，夜间复用既有 `data-theme="dark"` 而不叠加第二套暗色，避免双暗色冲突；
  - 引证区与提示文字硬编码暖色（`#fbf7ef` / `#8a7a63` / `#9c6b30` 等）改 `--white` / `--line` / `--gold` / `--ink-soft`，消除夜间刺眼浅块；
  - `MutationObserver` 同步昼夜按钮与面板档位高亮，避免按钮状态与真实主题不同步。
- **验收（可复算）**：
  - 导读线 headless 断言 20/20（四档字号正文同号、三档行距实测行高 36/40/44px、四纸色变量值、夜间 `data-theme=dark` 且不叠 `reader-paper`、落盘内容、刷新保持、两线双向继承、无导读内容视角页不出面板、375px 面板不溢出与无横向滚动、触控目标 ≥44px、Esc 关闭、无 JS 报错）；
  - 原文线回归 15/15（`.article` 跟随、四档同号、行距、纸色、无报错）；
  - 对比度：精读正文 12.79–15.99:1、导读块 12.86–16.25:1、小字提示 5.17–7.13:1，四纸色全部过 WCAG AA；
  - 线上复测 8/8（`dimensionscosmos.pages.dev` 面板存在/默认 20px/切 26px/夜间/刷新保持/375px/无内容页无面板/无报错）；CI `ingest-deploy` success，本地与线上一致。

### UX-4 移动端触控与密度（P1，0.5 人日，本机）

- 方案：分类 chip 高度提到 44px、间距 10px；卡片内边距随 `max-width:480px` 调整；筛选行横滚加渐隐提示。
- 验收：375px 下 chip 命中区 ≥44×44；无横向溢出；首屏可见 ≥2 张卡片。

### UX-5 检索埋点聚合（P1，1 人日，marvis）

- 方案：CF Worker 收 `dc_search_miss` 批量上报（localStorage 攒 20 条或离开页面时发），按周聚合输出"高频搜不到书名 TOP20"与"命中 0 的关键词"到 `docs/`。
- 验收：端点上线、周报落档、TOP20 转为补书候选并进入 `docs/CORPUS-SELECTION-*` 讨论。
- 依赖：marvis 外网；若成本超预算，降级为本机导出 JSON 人工汇总。

### UX-6 书籍详情元数据显性化（P0，1 人日，本机）

- 现状：`version.text`（底本）、`version.structure`（卷次）、`version.readingTip`（读法）、`grade/score` 已在 `index.json`，详情页呈现弱。
- 方案：详情页加"底本与版本"信息块（底本 / 卷次结构 / 阙卷声明 / 读法建议 / 等级徽标），专家型用户可扫读；阙卷用醒目但非警告色标注（如"表部卷十五下、十九下底本以表略省略"）。
- 验收：汉书等含 `structure` 的书全部展示；无 `structure` 的书不出现空块。

### UX-7 检索式查询与引用导出（P1，2 人日，本机）

- 方案：支持 `作者:班固`、`朝代:东汉`、`分类:史部` 前缀语法（客户端解析，未知前缀按全文处理）；排序切换；详情页与章节页提供"复制引用"（格式：`作者. 书名. 底本. 维点图书馆, 2026. 章节`）。
- 验收：三类前缀各有命中案例；复制结果可粘贴入 Word 且不丢字；无 JS 时退回普通检索。

### UX-8 首屏引导与精选（P0，1 人日，本机 + marvis 供数）

- 方案：首页加"从这里开始"三步（选一部 → 选一位大师 → 读一章），并接 `featured`（人工精选 6 部，按读者类型分栏：入门 / 经典 / 专题）与 `recently`（新增书目）。
- 验收：首屏 3 秒内可见"开始阅读"主按钮；精选卡片可直达详情；移动端首屏不出现三列挤压。
- 依赖：`index.json` 需 `featured` / `recently` 字段（marvis M-UX4 供数）。

## 8. 不做什么（范围边界）

1. 不做账号体系与云端同步：进度先落 `localStorage`，跨端同步留待后端就绪。
2. 不做全文检索引擎（如 Meilisearch / ES）：112 部 + 客户端索引足够；300 部以上再评估（UX-7 预留接口）。
3. 不做注疏体排版升级：现有注疏底本噪音问题属数据侧（marvis M-4），不在前端掩盖。
4. 不推翻现有品牌视觉：只做密度、触控、字号与层级修补，不动主色与字体家族。
