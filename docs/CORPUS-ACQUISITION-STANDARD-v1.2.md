## 第 1 章 根本原则

八条原则，按效力从高到低排列。前四条决定「选不选」，后四条决定「做成什么样」。

### P1 认知增益优先于名气与收藏欲
选书的唯一目的是**让读者读完以后换一种看法**，不是把名著凑齐、不是把四库搬空。
可操作的判据：一部书如果只能提供"知识点"而不能提供"可搬走的思维工具"，D1 最高只能给 3 分；D1 < 3 的书，除非补结构性空缺，一律不进正式名额。

### P2 结构完整性优先于数量增长
扩容的合格标准不是"多了几部"，而是**有几条主线从断到通**。
判断方式：先看覆盖矩阵（经/史/子/集 × 断线清单），再看排名。宁可一轮只加 12 部而打通 4 条断线，也不加 40 部把子部堆到 60 部。

### P3 可读完优先于全本情结
单部正文 1 万–200 万字是硬边界（约束 A）。
- 少于 1 万字：不入正式库，进"选读/单篇"层；
- 超过 200 万字：只做选本或分卷（如《通志》只取二十略、《海国图志》只取关键卷），且必须在版本说明里写明"选本"；
- 70 万字级（红楼梦、三国演义）必须配"可读完方案"（按回目/主题选章），否则视为未交付。

### P4 可解释优先于可陈列
一部书入库的前提是**它撑得起导读**（约束 B）：有历代注疏或成熟研究传统，AI 导读能产生"原文之外"的增益。
无注疏、无研究积累的纯资料汇编，即使名气大，也只能进观察池。

### P5 可核验优先于便捷
- 底本必须来自公有领域或明确许可来源（本地殆知阁归档 = 漢籍リポジトリ / 四库，CC BY-SA 4.0；维基文库 PD）；
- 每一部书必须能说出**底本文件名、版本、许可**，写入 `work_profiles.version_text / version_source`；
- 不使用来源不明、无授权说明、盗版排印的电子文本。

### P6 可复算、可审计优先于主观判断
- 分数只能来自 `data/corpus_scores.csv`，且每部必须有锚点依据，禁止"凭印象给个分"；
- 排名与分档由脚本按权重算出，人工只能通过**结构校正条款**（§2.4）显式覆盖，且必须写明理由；
- 任何落选书目，必须能在 `gate_note` 或分数里找到落选原因；任何入选书目，必须能追溯 5 个分数 + 1 条 D3 依据（或 provisional 标记）。

### P7 单一规则来源，版本化演进
标准只有一份。要改规则，改本标准并升版本号（v1.0 → v1.1），在附录 C 记变更；禁止在单轮执行中"临时口头放宽"。
规则的改动必须**向后兼容**：新增条款不得使既有 88 部的结论失效，只允许更严格或更细。

### P8 交付闭环优先于入库动作
"写进数据库"不算完成。一部书只有在满足第 2 章 §2.8 的**六项交付标准**（入库完整、稳定引用、元数据、版本说明、站点可读、可发现性）之后，才算交付。
未闭环的入库是负债，必须在 §3.6 缺口账本登记，且下一轮优先偿还，不得继续堆新书。

### P9 不完备必须显式声明
残卷、辑本、选本、单章本（如《幼学琼林》仅存卷一、二；《海国图志》单章；55 个短章）**可以做，但必须标注**：`version_text` 说明残缺情况，章级质量标 `incomplete`，站点不对外声称"全本"。
隐瞒残缺比残缺本身更严重——它破坏的是整个库的可信度。

### P10 有界扩张
候选池只从**四部要籍 + 蒙学 + 近世思想**三个来源枚举，规模维持 100–150 部。每部候选必须能回答"补哪个缺口"（`gap` 字段）。
说不出缺口的书不进池；池子不做无限扩张。池外的书要进，必须先论证"它开了一条新主线"，并写进附录 C。

## 第 2 章 基础标准

### 2.1 部类口径与覆盖矩阵

- 四部归属统一取**带「部」字**的形态：经部 / 史部 / 子部 / 集部。蒙学归子部，近世思想按内容归史部或子部（《海国图志》归史部、《天演论》归子部），但 `gap` 字段必须标「近世」。
- 覆盖矩阵按「部类 × 主线」维护，主线是最小审计单位：

| 部类 | 必须打通的主线 |
|---|---|
| 经部 | 五经 → 四书 → 三礼 → 春秋三传 → 小学（训诂/音韵/文字） |
| 史部 | 纪传 → 编年 → 政书 → 地理游记 → 史论/史评 → 方志 |
| 子部 | 诸子（儒道法名墨）→ 佛道 → 科技（农医算工）→ 兵学 → 笔记小说 |
| 集部 | 诗文别集 → 总集选本 → 词 → 戏曲 → 白话小说 → 文论诗话 |
| 特设 | 蒙学（最低门槛入口）、近世（1840 后转型） |

主线内已有 ≥1 部代表作即视为"通"，全缺或只有 1 部视为"断"。**每轮扩容必须至少打通 2 条断线**，否则本轮不立项。

### 2.2 五维评分（沿用模型 v1.0，权重不变）

综合分 = 0.30·D1 + 0.25·D2 + 0.20·D3 + 0.15·D4 + 0.10·D5，每维 0–5。

| 代号 | 维度 | 权重 | 核心问法 |
|---|---|---|---|
| D1 | 认知增益 | 0.30 | 读完它，思维方式会不会被改造？ |
| D2 | 思想内涵深度 | 0.25 | 能否被反复读、反复解释？ |
| D3 | 全球影响力 | 0.20 | 汉文圈之外是否被真实翻译、引用、教学？ |
| D4 | 流通程度 | 0.15 | 今天读者能否顺利拿到并读下去？ |
| D5 | 话题度 | 0.10 | 是否还在当代公共讨论与再创作中活着？ |

评分纪律：
1. 必须写**锚点档位依据**（不是自由发挥），依据写入 `note`，格式 `D1=4(强解释力模型,需桥接:…)`；
2. D4 由两段合成：`d4 = (d4_avail + SIZE_SCORE[size_class]) / 4 × 5`，`d4_avail` 取值 0=需校勘/拆分/残缺、1=有公有领域底本、2=本地底本可直接读；`SIZE_SCORE`：S1=2.0（≤5 万字）、S2=1.0（5–20 万）、S3=0.5（20–60 万）、S4=0.0（>60 万）；
3. D3 只有 `status=VERIFIED` 才计入加权，否则一律走 provisional 归一化（其余四维重归一化），**禁止用印象分填 D3**。

### 2.3 六道 Gate + 三道技术闸（先过滤，后评分）

行政门槛（任一不过即不进评分）：

| 代号 | 门槛 | 判定方式 |
|---|---|---|
| G1 | 汉文典籍（域外汉文另立专题） | 人工 |
| G2 | 公有领域底本可获取 | 本地归档/在线抓取试跑 |
| G3 | 非纯目录/纯索引；类书、总集须能拆出独立单元 | 人工 + 结构探针 |
| G4 | 去重：同书不同注本/选本只入 1 个代表本 | 查 `works` |
| G5 | 篇幅 1 万–200 万字（超限须给选本方案） | 抓取后实测 |
| G6 | 不与现有库重复（`seed_title` / `ws_title` 比对） | 查 `works` |

技术闸（v1.0 新增，防止"分数够但做不出来"）：

| 代号 | 闸门 | 判定方式 |
|---|---|---|
| T1 | 底本纯度：白文本 > 注疏本 > 辑本/残本 | 探针 + 版本说明 |
| T2 | 结构可切：目录块可切除、标题模式可枚举 | `probe_structure.py` 试切 |
| T3 | 章级可用：0 空章、0 重复章、单章 ≥ `min_chars` | dry-run 报告 |

### 2.4 分档与结构校正

| 档 | 综合分 | 处置 |
|---|---|---|
| S | ≥ 4.20 | 本批立即执行 |
| A | 3.60–4.19 | 本批或次批，按入选顺序排 |
| B | 3.00–3.59 | 观察池，仅结构补位时入选 |
| C | < 3.00 | 不做 |

**结构校正**（不入加权分，人工复核时覆盖机械排序，必须在结论文档写明）：
B 档以上的候选，若命中未打通主线（三礼、春秋三传、小学、政书、地理、史论、佛道、科技、戏曲、白话小说、蒙学、近世），可**上调一档**入选。
C 档不因结构校正升档（认知增益不足的书占名额会稀释整个库）。

### 2.5 入选顺序（并列决序）

综合分降序排列；同分或跨档竞争同一批名额时，按下列顺序逐级决出，前一级相同才看下一级：

| 级 | 决序规则 | 理由 |
|---|---|---|
| T1 | 缺口优先级：断线主线 > 半通主线 > 已通主线 | P2 |
| T2 | 篇幅：S1 < S2 < S3 < S4 | 短周期可闭环，先出成果再啃大部头 |
| T3 | 底本纯度：白文本 > 注疏本 > 辑本/残本 | T1，返工成本最低 |
| T4 | 导读方法增量：能为尚未覆盖的导读方法提供样本者优先 | 产品侧收益 |
| T5 | 题名字典序 | 仅为保证排序确定性 |

### 2.6 单批容量规则

一批（batch）同时满足三条才成立，否则拆批：
1. 部数 ≤ 20；
2. 预计正文总量 ≤ 150 万字（按 `size_class` 估算，导入后以实测为准）；
3. 新增切章模式 ≤ 3 种（同一批里混入过多未知结构会拉高返工率）。

### 2.7 底本、切章与元数据标准

**底本**：`data/sources/daizhige/*.md`，文件名登记在 `pipeline/daizhige_corpus_config.py`；每部配置 `note` 必须含底本版本 + 许可（`底本：殆知阁归档 … CC BY-SA 4.0`）。

**切章**（`pipeline/daizhige_import_core.py`）：
- 切章模式按底本实际结构选：`hui`（回）、`chu`（出）、`juan`（卷）、`pian_num`（篇名+汉序）、`list`（固定标题清单）、`tiao`（序号独占行）、`pin`（【品名】）、`mark`、`yinyan`；
- 目录区必须先切除：优先 `cut_toc`（遇「目录/目次」字样截到首段长正文），无目录字样时用**重复标题块切除**（文件前 45% 内首行 a 与 i+5..i+400 内空白归一化相等行 k，中间全短行且非空占比 ≥0.6 即整段删），回目型标题 `maxlen` 放宽到 40；
- 全角空格必须两端统一后再比较，否则重复块识别会漏；
- `min_chars` 按文体定：诗词选本 15–50、语录/笔记 200、史部/诸子 300；
- 单章低于 `min_chars` 记 `incomplete`，不得静默丢弃或合并。

**切章四项增强能力**（v1.1，batch4 落地，配置项写在 `pipeline/daizhige_corpus_config.py`）：
| 能力 | 解决的问题 | 典型底本 |
|---|---|---|
| `join_next` / `join_max` | 标题被拆成「卷次行 + 篇名行」两行（`卷X` 独占一行，篇名在下一短行） | 抱朴子内篇 |
| `title_clean` | 标题带冗余前缀或句读符号（`大戴礼记卷X` 去前缀、`卷X兴造论。` 去句号） | 大戴礼记、园冶 |
| `index_prefix` | 底本标题无编号，需按出现顺序自动补 `第X` 序号 | 西厢记 |
| `re` 放宽（长标题） | 标题本身超短行阈值（`大唐西域记卷第X(三十四国)`） | 大唐西域记 |
| `start_re` | 无「目录」字样，但正文前有篇目/提要区，需按正文首句定位起点 | 释名（「释名叙」为界） |
| `shortline` + `no_strip_dup` | 词集按词牌切章：词牌为短行，且不可走重复块切除 | 稼轩词、陶庵梦忆 |

**坑：`group_re` 误配会导致标题重复入章**（西厢记 `○第一折` 曾因分组正则重复匹配，改用 `index_prefix` 后消除）。凡底本标题以符号起头（`○`/`【】`/`·`），先验证 `group_re` 必要性，能不用则不用。

**短制经典口径（v1.2.1 已生效条款，2026-11-02 业主裁定方案 A）**：§P3 的「单部 1 万字下限」自 v1.0 起从未执行（全库 13 部短制：金刚经、老子、孙子兵法、诗品、人间词话、中庸、大学、孝经、二十四诗品、三字经，batch5 增心经、漱玉词、周易参同契），与 P7「不得使既有结论失效」冲突。**裁定口径：有独立注疏传统、概念密度高、可单次读完的短制经典准予入正式库**，但 `version_text` 首句必须声明「短制（正文 N 字）」，N 取 `works.total_chars` 实际值、须可复算；碎片、资料性短篇、无注疏传统的短篇仍禁止入库。该条款不追溯撤销既有 13 部，其合规状态由「程序性瑕疵」转为「合规（短制条款）」。新增短制入库须同时满足：① 有独立注疏传统；② 可单次读完；③ 首句标注齐备。缺任一项不得放行。

**选本/分卷子批口径（v1.2.3 新增，batch7 首次落地）**：候选单部正文超 §2.6 单批 150 万字上限、或因体量致 P4「可读完」不成立者，不得因超容直接放弃，也不得整体压入单批，须另立「选本/分卷」子批，占用独立 batch 号与 work_id，规则如下：
1. **裁剪可复算**：必须由脚本按卷号白名单裁剪（batch7 用 `pipeline/slice_zhuzi_yulei.py`），裁剪脚本与卷号清单同时入库，禁止手工删改底本；
2. **选本即选本**：`seed_title` 须带「选本」字样，`version_text` 必须写明「取卷 X–Y …，余 N 卷未收，属选本，非全本」，不得对外称全本（§P9）；
3. **主线优先**：选本卷次按主线断线优先取（如理学语录取理气/性理/学 13 卷成轴），并写明取舍理由；
4. **余卷留账**：未收卷次进缺口账本，后续可分「选本二」「选本三」续批，各占独立 work_id；
5. **短制条款不适用**：选本体量按其实际入册字数计，仍须满足 §P3 单部 1 万字下限，不受短制条款豁免。

**元数据**（`pipeline/backfill_works_meta.py`，幂等，默认 dry-run）：
`author` / `dynasty`（与旧库值域一致：先秦/战国/西汉/东汉/三国魏/西晋/东晋/南朝梁/南朝陈/后秦/北魏/唐/五代/北宋/南宋/元/明/清/清末）/ `bu`（带「部」）/ `ws_title`（OpenCC s2twp 繁体题名）。

**引用层**：每章一条 `ref`，格式 `dc:<work-key>/c<NNN>`，全库唯一（`scripts/migrate_ref.py --apply`，写前快照）。

### 2.8 验收：六项交付标准

| # | 标准 | 判定口径 |
|---|---|---|
| S1 | 入库完整 | `works.status='ok'`，章数/字数落库，0 空章、0 重复章 |
| S2 | 稳定引用 | 每章一条 `ref`，全库唯一，0 冲突 |
| S3 | 元数据 | `author` / `dynasty` / `bu` / `ws_title` 齐全，值域合规 |
| S4 | 版本说明 | `version_text`（底本+残缺声明）/ `version_source`（许可）齐备 |
| S5 | 站点可读 | 书详情页 + 阅读页（10 种导读方法入口）+ `book-*.json` + 章节 JSON |
| S6 | 可发现性 | 每章稳定短链页 + sitemap 收录 |

六项全绿才算交付；任一未达成即为负债，入缺口账本。

## 第 3 章 运行秩序

### 3.1 一轮扩容的七步

| 步 | 动作 | 产物 / 证据 |
|---|---|---|
| ① 盘基线 | 查 `works` 构成、覆盖矩阵、缺口账本 | 本轮立项说明（打通哪几条断线） |
| ② 过 Gate | 候选池逐部过 G1–G6 + T1–T3 | `data/corpus_local_match_*.csv`（底本可得性） |
| ③ 评分 | 逐部五维 + 锚点依据，D3 未核验标 provisional | `data/corpus_scores.csv` 追加行 |
| ④ 排序定档 | `--report` 复算，分档 + 结构校正 + 并列决序 | `data/corpus_scores_ranked.csv` + 结论文档 |
| ⑤ 试切 | 单部 dry-run，看章数/章均字数/空章 | dry-run 报告（不入库） |
| ⑥ 写库 | 分批 `--apply`，随即跑元数据/引用/构建 | `guji.db` + `work_profiles` + `dist/` |
| ⑦ 验收留档 | 六项交付核对 + commit + 结论文档 | git commit、`docs/CORPUS-EXPANSION-*.md` |

任何一步失败，回到上一步修正，禁止跳过 Gate 直接写库。

### 3.2 批次与编号

- 批次号连续递增（batch 1–7 已完成 63 部，下一批为 batch 8），配置集中在 `pipeline/daizhige_corpus_config.py` 的 `batch=` 字段；batch7 为「选本/分卷」子批（§2.7 新条款）；
- `work_id` **连续分配、不留空洞**：batch1–3 用 101–138，batch4 用 139–145，batch5 用 146–158，batch6 用 159–161，batch7 用 162，下一批从 163 起；（原「每批预留 50 号」条款在 batch4 执行中证明会造成大量空号，已废止）
- 批次顺序 = 入选顺序（§2.5），不得按识字难度或心情调整。

### 3.3 标准命令序列

```bat
REM 1. 复算排名（0 错误才继续）
.venv\Scripts\python.exe pipeline\score_corpus.py --report

REM 2. 单部试切（dry-run；--title 直接给书名）
.venv\Scripts\python.exe pipeline\run_import.py --title 大戴礼记 --detail

REM 3. 整批写库（先 dry-run，全 ok 再加 --apply）
.venv\Scripts\python.exe pipeline\run_import.py --batch 4
.venv\Scripts\python.exe pipeline\run_import.py --batch 4 --apply

REM 4. 元数据对齐（默认 dry-run，只补空缺；脚本不支持 --batch，全库幂等）
.venv\Scripts\python.exe pipeline\backfill_works_meta.py --apply

REM 5. 引用层 / 站点构建 / 校验
.venv\Scripts\python.exe scripts\migrate_ref.py --apply
npm run build
```

> 入口纪律（v1.1）：批量导入的唯一入口是 `pipeline/run_import.py`；`pipeline/import_daizhige_corpus.py` 只作底层库被调用，直接执行它会因缺 `batch/title` 参数抛错，不作为命令行入口。
> 写库前先手动快照 `data/guji.db` 到仓库外（`.backups/`，已入 `.gitignore`），**不得**把整库快照留在 `data/` 里被误提交。

### 3.4 审计要求

每轮结束时必须能回答四个问题，答不上就是本轮不合格：
1. 这轮加了几部、打通了哪几条断线？
2. 每部书的 5 个分数与依据在哪里（`corpus_scores.csv` 行号）？
3. 每部书的底本文件、版本、许可是什么（`version_text`）？
4. 全库现在有没有新增负债（空章、缺 ref、缺元数据、残卷未声明）？

### 3.5 变更留档

- 结论文档命名 `docs/CORPUS-EXPANSION-YYYY-MM.md`，含：基线 → 候选 → 排名 → 本批名单与理由 → 执行结果 → 未决事项；
- commit message 用 `corpus(batchN): 新增N部 + 一句断线说明`；
- 数据库变更前自动快照（`temp/backups/guji.db.<ts>.bak`），保留最近 3 份。

### 3.6 缺口账本（每轮更新）

固定四栏，写在最新结论文档末尾：

| 类型 | 内容 | 偿还方式 |
|---|---|---|
| 结构缺口 | 仍未打通的主线 | 下一轮优先立项 |
| 数据缺口 | `wikidata_qid`、`compiled_year`、AI 导读覆盖率 | 联网后回填 / 批量生成 |
| 质量缺口 | 残卷、单选本、短章（`incomplete`） | 换底本重做或版本说明加固 |
| 流程缺口 | 未推送提交、未跑构建、未核验 D3 | 当轮偿还，不得跨两轮 |

### 3.7 例外与仲裁

| 情形 | 处理 |
|---|---|
| 综合分高但违反 P3（读不完） | 降为"选本/分卷"方案，不给正式名额 |
| 用户点名要某部书 | 用户指令优先，但仍须过 G1–G6；不达标要如实说明代价 |
| 结构校正与排名冲突 | 结构校正生效，但必须在结论文档逐部写理由 |
| 底本只有注疏本 | 可用，但 D4 的 `d4_avail` 取 1，且版本说明写"注疏本" |
| 底本残缺（辑本/残卷） | 可入库，`quality=incomplete` + 版本声明，不得计入"打通主线"的完整证据 |

### 3.8 回滚

1. 单部误入：按 `work_id` 删除 `works` + `chapters` 行，重建构建；
2. 整批误入：`temp/backups/guji.db.<ts>.bak` 还原 + `git revert <commit>`；
3. 回滚后必须在结论文档记一行"回滚记录：批次/原因/影响范围"。
