# 体验准则（项目级约束，2026-11-05 起生效）

- 制定人：项目负责人
- 适用域：全部前端与内容侧体验（`src/**`、`docs/UX/**`、后续任何界面层工作）
- 效力：高于任何单张 UX 任务卡、任何"业界惯例"论据、任何 AI 自主提议。与本文冲突的方案，一律不实施。

---

## 1. 唯一坐标

**一切体验只服务两件事：内容（古籍）与质量（体验、审美、动线）。**

- 内容：底本、导读、校勘、引用，是产品本体。任何界面元素的价值，以"是否让人更接近内容"为唯一判据。
- 质量：体验（可用、可读完）、审美（克制、留白、不喧哗）、动线（最短路径抵达正文）。
- 反坐标：增长、留存、转化、身份分层、引导漏斗、运营位——**本项目不以此为设计目标**。

## 2. 准入闸门（硬约束）

任何功能、模块、样式的新增，**必须**同时满足：

1. **用户提出**：由项目负责人明确提出，或经其书面批准（写进 `docs/UX/` 并留字）。未被提出的，**不得实施**。
2. **服务内容**：能指出它让人更快/更好读到哪一类古籍内容。指不出，即不成立。
3. **改既有而非开新路径**：优先优化已有动线（检索 → 书 → 章 → 正文），不得新增并列路径、并列入口、并列叙事层。
4. **删除无损检验**：假设把该元素删除，内容与动线是否受损？若无损，说明它不该存在。

> 四条中任一不满足 → 不实施。没有"先做出来再评估"的例外。

## 3. 论证与实现分离（AI 协作纪律）

- AI 可以研究、可以论证、可以出方案、可以写评估文档；**论证本身不等于授权**。
- 未经明确批准，不得把"分析结论""行业标杆差距""已具备条件"直接转为代码提交。
- 对未批准方向的正确做法：写清选项、成本、风险，停在纸面，等裁决。
- 说"顺手做了""业界标配""成本很低"不是理由；成本低不等于该做。

## 4. 纠偏纪律（回滚优先）

- 用户否定某项已交付内容时：**即刻回滚，不辩护、不打折、不"改良保留"**。
- 回滚必须是净删除：移除组件、文案、类型、校验脚本、构建脚本入口，回到该方向引入前的原貌。
- 允许保留的只有证据性文档（审计、决策记录），且必须在文首标注 `REVERTED` 与失效范围，避免被后来的协作者误读为现行方案。
- 回滚后必须复跑回归，证明"删除未破坏既有内容与动线"。

## 5. UX-8 教训（反面案例，2026-11-05 回滚）

UX-8（首屏双 CTA + 三步条 + 四身份分栏 + 精选 6 部 + 两条降级分支）在工程上达标：纯静态零 JS、1756 行净增删可控、静态 48 项 + 线上 + 三套回归全绿。它仍然被否，原因是**判断错误，不是执行错误**：

1. **把"业界标配"当成"本项目该有"**。首屏引导、身份分栏、精选位是消费型内容产品的留存装置，与"古籍 + 克制审美 + 最短动线"根本不同源。
2. **把用户开放执行当成了方向批准**。用户开放的是执行，不是设计授权；方案层从未被认可，却被直接做成了可上线形态。
3. **在前置论证里用工程指标替代方向判断**。可访问性、性能、降级完备度都达标，但方向错了，达标只是把错误做得更精致。
4. **新增叙事层侵入首页**。首页本应是"一句话定位 + 检索 + 数量事实 + 古籍视觉"，UX-8 在其上叠了三层解释性 UI，稀释了内容本身。
5. **证据充足感造成沉没成本**。67/67 通过的报告会诱发"再优化一轮"的冲动，而正确动作是回滚。

**归纳为一句**：工程质量只能证明"做得对"，不能证明"做得该"。判断"该不该"的权力只在用户。

## 6. 交付前自查（每次界面类提交前逐条回答）

| # | 自问 | 不合格信号 |
|---|---|---|
| 1 | 这个元素是用户提出的吗？出处在哪句话？ | 找不到原话 |
| 2 | 它让人更接近哪一类古籍内容？ | 只能答"提升体验/转化" |
| 3 | 它是优化既有动线，还是新增了一条路径？ | 新增入口/新增区块 |
| 4 | 删掉它，内容会受损吗？ | 不会 |
| 5 | 我是否在替用户决定产品形态？ | 是 |

五项全部通过才提交；任一项含糊，先停下来问，不要先做。
