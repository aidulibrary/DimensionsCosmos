# 36 篇导读阶段性交付方案

> 生成时间：2026-11-01
> 口径：4 部书（论语 / 老子 / 颜氏家训 / 世说新语）× 9 种读书法 = 36 篇

## 一、先纠正一个事实

过去按"库里有多少条记录"统计，得出 12/36 的进度。加入体检闸门后按**质量口径**重算，真实情况是：

| 指标 | 数量 | 说明 |
|---|---|---|
| 过闸可用 | 1 | 论语 × 朱熹读书法 |
| 有记录未过闸（需重做） | 11 | 段落数不足 5 / 论述不足 120 字 / 引证全落在 b001 等硬伤 |
| 完全缺失 | 24 | 从未生成 |
| **实际待生成** | **35** | 需重做 11 + 缺失 24 |

也就是说，旧 12 篇基本是「初版可用但达不到验收线」的草稿，不能算交付。

## 二、阶段划分

生成依赖大模型算力，本机跑不动（qwen3:4b 本机 2.9 tok/s、单篇 60 分钟），因此生成阶段必须搬异机；本机只承担"不耗算力但必须做对"的部分。

|---|---|---|---|
| P0 | 质量闸门与发布链路 | 本机 | **已完成（本轮）** |
| P1 | 35 篇生成 | 异机 | 待启动（需算力） |

## 三、P0 质量闸门与发布链路（已完成）

| 交付项 | 文件 | 效果 |
|---|---|---|
| 导读体检器 | `pipeline/qa_guides.py` | 从库重解析引证 URN、比对原文，输出段落数/字数/跨章/占位符等硬指标，`--gate` 导出白名单 |
| 发布拦截 | `scripts/gen-data.mjs` | 未过闸的导读不进前端数据，页面自动降级为"筹备中"，不再把草稿当成品上线 |
| 重做识别 | `pipeline/batch_guides.py` | 以闸门判定完成度，`~` 标记未过闸旧篇并排进重做队列；`--plan-out` 导出 Markdown 台账 |
| 空页不索引 | `src/pages/read/[slug]/[method].astro` | "未上架"页与付费墙页一律 `noindex` |
| 商业化开关 | 同上 | `COMMERCE_ENABLED=false`：无内容的视角不再被渲染成"请解锁"，避免对空内容收费 |
| sitemap 净化 | `scripts/postbuild-seo.mjs` | 跳过页面自身 `noindex` 的 URL，sitemap 从 550+ 条降到 121 条纯内容页 |
| 结构化数据 | `src/pages/read/[slug]/[method].astro` | 已上架导读输出 `Book + Article + BreadcrumbList` JSON-LD，与 5400+ 原文页区分 |

构建验证：`613 page(s) built`，`[guides] 质量闸门拦下 11 篇`，`[seo] 121 个 URL`，论语 zhuxi 页确认输出 JSON-LD、正文 36 段 7317 字、9 处原文引文与"本段引证"锚点。

## 四、P1 生成（异机，按书分批）

单批控制在 2 小时内，便于中断续跑（`--max-seconds` 到点优雅停止，已生成的不会丢）。

| 批次 | 范围 | 篇数 | 预估 |
|---|---|---|---|
| 批 1 | 论语 | 8（5 重做 + 3 新增） | ~90 分钟 |
| 批 2 | 老子 | 9 | ~100 分钟 |
| 批 3 | 颜氏家训 | 9 | ~100 分钟 |
| 批 4 | 世说新语 | 9 | ~100 分钟 |

异机执行口径（与既有套件一致）：

```
git clone / git fetch && git checkout main
拷贝 guidepack.db → data/guji.db
ollama pull <模型>
python pipeline/batch_guides.py --run --only-book 论语 --max-seconds 7200
python pipeline/batch_guides.py --export guides.json
```

回传后本机：`--import guides.json`（往返哈希一致，已演练）。

## 五、P2 回传验收（本机）

每批回传即走一遍，不等 35 篇全齐：

1. `qa_guides.py --gate data/guide-qa-gate.json` 复检
2. 未过闸的篇目直接回流下一轮重做，不带病上线
3. `node scripts/gen.mjs && npx astro build && node scripts/postbuild-seo.mjs`
4. 抽样人工读 2 篇，重点看引文是否与原文逐字对应（程序只能校验锚点，语感要人看）
5. 通过后 commit + push，Cloudflare 自动发布

## 六、P3 展示层与 SEO（本机，可穿插）

- 导读页内链：文末"换个视角"已具备，补充同书章节级跳转
- 分享卡：og:image 目前是站点统一图标，导读页可生成带书名+方法名的动态图
- sitemap 分片：URL 超过 5 万才需要，当前 121 条，长期观察即可
- 原文页与导读页的互链密度是收录关键，优先做

## 七、P4 商业化前置评估（文档级）

- 付费墙已用 `COMMERCE_ENABLED` 单开关隔离，启用前需确认：定价页与空内容页的隔离、退款条款、发票
- 免费/付费方法的边界要写进方法定义（当前 9 法里仅朱熹法 `free=true`）
- 结算依赖第三方，涉及资质与主体信息，属需人工准备的项，不在自动化范围
