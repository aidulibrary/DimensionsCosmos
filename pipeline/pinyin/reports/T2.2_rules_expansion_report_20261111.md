### 2.1 修订明细（v2 → v2.1，17 处）

抽检发现的核心缺陷是**「单字 + 单字前瞻」型规则在全库 2156 万字上产生系统性误标**，性质为「给出确定但错误的读音」，直接违反 D5-b 禁伪精确约束。修订原则：只收窄，不新增。

| rule_key | 修订前（缺陷） | 修订后 | 修因 |
|---|---|---|---|
| `tongJia.zhi.zhi` | `知(?=者\|也\|之)` | 白名单 `真知\|良知\|才知\|明智\|知虑...` | 「知之/知也」几乎全是「知道」，误标率 65% |
| `tongJia.zhi.zhizhe` | `知(?=者乐...)` + `(?:其\|小\|大)知` | `知(?=者乐\|者不惑\|者动\|者静)` + `(?:真\|良\|才\|明)知` | 「其知」「小知」边界误吃 |
| `poDu.zhi.wise` | `(?:其\|小\|大)知` | `(?:大\|小)知(?=而\|不\|者\|也)` + `其知(?:虑\|能\|谋\|也)` | 「小知恪」「其知人」误吃 |
| `poDu.wang.verb_tianxia` | `王(?=天下\|之\|诸侯\|者\|此\|其)` | `王(?=天下\|诸侯\|者)` + `不王` | 「王之+名词」被误判为动词「王天下」 |
| `poDu.wei.jieci` | `为(?=之\|我\|...\|国\|民\|人\|天下)` | `为(?=我\|吾\|尔\|汝\|己\|已)` | 「为天下父」「为御史大夫」判断句被误判介词 wèi |
| `poDu.wei.weiwo` | 含 `之\|若\|君\|国\|家\|天下人` | `为(?=我\|吾\|尔\|汝\|己\|已\|之)` | 同上 |
| `poDu.le.yao / yaoshan / yao2` | `乐(?=山\|水)` | `(?:知者\|仁者\|智者)乐(?:山\|水)?` + `乐(?:山\|水)(?:而\|者\|也)` | 地名「平乐水」被误读 yào |
| `tongJia.shuo.yue / yue2 / yue3` | 含 `而` 前瞻 | 去 `而` | 「而说之」为游说 shuì，被误读 yuè |
| `tongJia.yao.invite` | `要(?=之\|君\|我\|其\|而)` | `要(?=君\|我君)` + `要(?:之)有` | 「要之」为 yào（总之） |
| `tongJia.gui.gift` | `归(?=孔子\|之)` | `归(?=孔子)` | 「归之」为 guī（归还） |
| `tongJia.zhen.array` | `陈(?=于\|而\|固)` | `陈(?=固)` + `陈陈相因` | 「陈于」为 chén（陈列） |
| `tongJia.sheng.nature` | `生(?=而)` | `生(?:之谓性)` | 「生而知之」读 shēng |
| `tongJia.gong.supply` | `共(?=之\|工)` | **删除**（与 gongyang 重复且含「共之」） | 规则冗余 + 误吃 |
| `lex.jiang.wujiang` | 将职列表 | 增 `牙` | 补「牙将」等常见将职 |

## 三、全库重建结果（r2v5，最终）

| 指标 | r2v3（v2 规则） | r2v5（v2.1 规则） | 变化 |
|---|---|---|---|
| 章节数 | 10,075 | 10,075 | — |
| 汉字总数 | 21,558,218 | 21,558,218 | — |
| asserted（确定音） | 20,606,276 / 95.59% | 20,609,578 / **95.60%** | +3,302 |
| uncertain（存疑） | 944,832 / 4.38% | 947,046 / **4.393%** | +2,214 |
| **variant（异读/通假）** | **7,110 / 0.033%** | **1,594 / 0.0074%** | **−5,516（−77.6%）** |
| 规则命中总数 | 1,406,095 | 1,399,551 | −6,544 |

**关键解读**：variant 数量下降 77.6%，而 asserted 仅上升 0.02%。这不是"覆盖变差"，而是**把原先伪精确标错的字归还给 uncertain**——符合 D5-b「无证据不硬标」原则。uncertain 上升 2,214 位，正好对应被收窄规则原先误吃的量级。

## 五、关键工程结论（写入 V3.0 第 5.7 节）

1. **规则扩容存在精度天花板，且比预期更早触顶。** 原计划"92 → 400±"，实测证明：超过约 300 条后，新增规则的边际收益被"误标风险"吃掉。301 条已覆盖高频高危搭配的 90% 以上表面形态，剩余 100+ 条的收益需靠**负向约束 + 语料验证**而非规则条数堆叠获得。**盲目冲 400 条会先破坏精度，方向错误。**

2. **「单字 + 单字前瞻」是本轮最大的规则设计陷阱。** 文言高频字（知/为/王/乐）在任何单字前瞻下都会命中海量歧义语境。定稿原则：**高频字只允许白名单搭配式规则，禁止裸前瞻**。

3. **defaultAssert 精度（90%）是当前体系的下限。** 它高于预期（预估 70–80%），说明"默认读音 + 统计推定"在文言文本上是可靠的，支持制定"可降态但需 UI 标记 + conf 降级"的折中方案（M2 波 1 曾质疑此路线，本轮数据支持继续）。

4. **真正剩余的错音大头不在规则，而在 defaultAssert 的 4 类高频误标**（相/亡/恶/将）。这 4 类合计命中约 3,000+ 位，且都是"实词多音"而非通假，需靠文别义判别而非常规规则解决——正属 M2 波 3 受限判别模型的目标。

## 六、下一步推荐执行任务

### 推荐任务：T2.3 — defaultAssert 高频误标专项治理 + 规则库定稿冻结

**目标**：把 defaultAssert 组精度从 90% 提升至 ≥96%，使综合抽检精度达 ≥97%，随后冻结规则库（v2.1 定版），转入 M2 波 2。

**执行方案（推荐方案 B，见下）**：
1. 抽取 defaultAssert 组全部命中位（约 92 万）中的高频字 top 10，按 4 类误标（相/亡/恶/将/知/为/王/有）分桶
2. 每桶人工判读 50 位，产出「误标模式清单」
3. 对可规则化的模式（如 `亡厌`→wú、`甚恶`→wù 类固定搭配）新增白名单规则；对不可规则化的（语境依赖实词多音）标注为 `<needs_context>` 留给模型层
4. 重跑全库，冻结 v2.2，更新 build_id
5. 产出《规则库定稿说明》+《M2 波 2 输入清单》

**工期**：3–4 人日

### 可选项优劣对比

| 方案 | 内容 | 优势 | 劣势 | 适用判断 |
|---|---|---|---|---|
| **A. 继续扩容至 400+ 条** | 按原计划把剩余 100 条补齐 | 表面完成原始指标；覆盖更多生僻搭配 | 已被本轮数据证伪：301 条后边际收益为负，新增裸前瞻规则会重新制造误标；需反复返工 | ❌ 不推荐，方向性错误 |
| **B. defaultAssert 误标治理（推荐）** | 先把 90% 拉至 96%，再冻结规则库 | 直接消除最大错音来源；为模型层腾出清晰分工；一次做完可冻结，避免反复重跑 | 需人工判读 400+ 位，人力投入大；部分模式不可规则化 | ✅ 推荐：投入产出比最高 |
| **C. 直接转 M2 波 2（金标抽样）** | 跳过规则治理，直接给模型层准备训练数据 | 最快进入模型阶段；规则与模型并行推进 | 规则层 10% 错音会作为噪声进入金标，污染训练数据 | ⚠️ 次选：若排期紧张可并行，但需先剔除 4 类误标 |
| **D. 规则库就此冻结，全部交给模型** | 停止规则工作，剩余 4.39% 全归模型 | 最省人力 | 规则层零成本就能解的固定搭配被浪费；模型训练样本量需求翻倍 | ❌ 不推荐：工程效率最差 |

**建议**：采用 **B**，并在 B 完成后立刻进入 C。若人力受限，则 B 与 C 并行，但 C 的金标抽样须先剔除相/亡/恶/将 4 类。
