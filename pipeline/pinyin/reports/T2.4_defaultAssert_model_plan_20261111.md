## 二、为什么叫"受限"判别模型

常规做法是端到端给全库注音，风险是覆盖掉成熟的规则判断。本方案把模型限制在三个维度：

| 受限维度 | 限定内容 |
|---|---|
| **受限域** | 只处理 `reading_source = defaultAssert` 的字位（约 1,600 万量级），规则命中位（poDu / tongJia）不进模型 |
| **受限任务** | 二分类判别"当前默认读音是否成立"，不做自由生成；输出 `1 = 成立`、`0 = 需改判` + 改判建议读音（来自该字候选读音集，闭集选择） |
| **受限输出** | 三态映射：`p ≥ 0.90 → asserted`；`0.60 ≤ p < 0.90 → uncertain`；`p < 0.60 → uncertain + 标记待人工` |

好处：规则的高精度不被稀释；模型只在自己擅长的同形歧义域出力；任何一位都可回答"为什么"。

## 三、数据方案

### 3.1 训练/验证集来源

| 来源 | 量 | 用途 |
|---|---|---|
| P0 金标（人工三态） | 1,200 位（B1 300 / B2 300 / B3 300 / B4 300） | 核心标签集 |
| 其中 B4 defaultAssert | 300 位 | **主训+主评**（唯一直接对应目标域） |
| 规则命中位（v2.5 抽检 271 位 + 30 位全对样本） | 301 位 | 负样本补充 + 防劣化验证集 |
| P1 滚动批次 | 每批 3,000 位（B4 占 40%） | 标注回流后增量，D+10 起 |

> **现实约束**：B4 仅 300 位做训练，样本偏薄。缓解见 3.3。

### 3.2 标签映射

| 人工三态 | 二值标签 | 权重 |
|---|---|---|
| `ok`（机器判读正确） | 1 | 1.0 |
| `wrong` + 修正读音 | 0 | 1.5（错例加权，提升召回） |
| `uncertain`（人也不能定） | 弃标 | 0（不参与训练，进 uncertain 池） |

标注台导出 JSONL 字段已含 `verdict` / `fix` / `bucket` / `char` / `ctx` / `machine`，可直接映射，无需二次清洗。

### 3.3 样本量不足的三条对策

1. **规则特征回灌**：把 350 条规则的命中证据（ruleId、命中片段、规则置信）作为特征，让模型在 300 位上学到"哪类规则形态容易翻车"，而非从零学字义。
2. **候选读音集约束输出**：模型的输出空间是该字的 pypinyin 候选读音（通常 2–4 个），不是开放词表，大幅降低样本需求。
3. **主动学习补样**：D+3 用首版模型在全库打分，取 `p ∈ [0.45, 0.65]` 的 300 位做第二批人工标注，优先补模型最不确信处。

## 四、特征方案（CPU 友好、可解释）

| 组 | 特征 | 维度 | 说明 |
|---|---|---|---|
| 字本体 | 目标字 one-hot / 字频 / 是否多音字 / 候选读音数 | ~ | 多音字表来自 pypinyin 词典 |
| 上下窗 | 前 1–3 字、后 1–3 字 的字符 n-gram hash | 2^16 | 捕捉"弟子/传曰/乐府"类词形 |
| 句法位 | 是否句首/句末、前邻是否虚词（之/而/以/于/其/所）、后邻是否助词（也/矣/乎/者） | ~20 | 动名同形多由句法位决定 |
| 规则证据 | 是否被某规则命中、ruleId 类别、规则在抽检中的历史精度 | ~30 | **关键特征**，直接把 T2.3 的经验注入 |
| 搭配强度 | 目标字与前/后邻字的点互信息（用 21.56M 字位全库统计） | 2 | 专名、官名识别 |
| 篇章 | 所属书（史记/后汉书/资治通鉴）、文体标记 | ~5 | 三书用字习惯不同 |

**明确不做**：不引入外部大模型推理（CPU 无独显，21.56M 字位跑不动）；不做字向量预训练（样本不足，收益低于成本）。

## 五、模型选型与算力

| 方案 | 说明 | 取舍 |
|---|---|---|
| **LightGBM（主选）** | 300 棵、深度 6、学习率 0.05，`num_threads=8` | 表格特征最优，训练秒级，GPU 不需要 |
| HistGradientBoosting（备选） | sklearn 内置，避免新增依赖 | 若 LightGBM 装不上直接换，指标差异 <1pp |
| Logistic 回归（基线） | 可解释、给上线前对照 | 只作基线，预期比 GBDT 低 3–5pp |

**算力实测口径**（i5-1340P / 8 线程）：
- 训练：300–3,000 样本 × ~120 特征，**<10 秒**
- 全库推理：约 1,600 万 defaultAssert 位 × 120 特征，按 3–5 万行/秒估算 **单遍 5–9 分钟**；分批落盘，可断点续跑

## 六、评估协议

1. **5 折分层交叉验证**，分层键 = 书 × bucket，确保三书均衡。
2. 主指标：B4 域准确率（目标 ≥96%）、混淆矩阵、错例性质归类（沿用 T2.3 的五类错因表，便于对照）。
3. 防劣化：规则命中组 301 位作为**固定验证集**，要求 ≥97%。
4. 校准：Brier score + 十分位可靠性图；`p` 必须可信，否则三态门限无意义。
5. 消融：去掉"规则证据"组 vs 保留，量化 T2.3 经验的贡献（写进报告，作为方法论沉淀）。

---

## 七、上线门禁（G3 阶段二）

同时满足才允许：
- B4 域精度 ≥ 96%
- 规则组精度 ≥ 97%（不劣化）
- 全库 uncertain ≤ 1.5%
- variant 误标率 ≤ 0.0074%
- 固定验证集 + 新增随机抽检 300 位人工复核通过

未达标处置：不放宽门禁，回退到"模型仅作 uncertain 优先级排序"，不参与 asserted 判定。

## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| B4 仅 300 位，过拟合 | 交叉验证虚高 | 强正则 + 按书分层 + 固定验证集；D+3 主动学习补样 |
| 标注者与模型口径不一 | 标签噪声 | 标注台已固定三态定义；`uncertain` 一律弃标不硬塞 |
| 全库推理内存峰值 | 16GB 机器可能吃紧 | 按书分批、流式特征、结果直接落盘 |
| 三书之外的书目泛化差 | 后续扩容需重训 | 特征以通用句法位 + 字 n-gram 为主，弱化书别依赖 |
| 模型给"看似合理但错"的读音 | 伪精确 | 三态门限 + 抽检复核；`p≥0.90` 才转 asserted |
